# Figma 展示页 → 网页（宽度锁 1920，高度自适应，连续滚动）

## 核心原则

设计稿宽度固定 1920、高度每页不同、并且要像长图一样连续往下看时，**不要用 `vh`/百分比去还原**，也不要给舞台写死高度。做法是：

1. 每页按真实像素高度排布在 1920 宽的舞台上，页与页首尾相接；
2. 整个舞台按「屏幕宽 / 1920」等比缩放；
3. 缩放用 CSS `zoom` 而不是 `transform: scale` —— `zoom` 会参与布局计算，所以滚动条高度、页面总长度都是对的，文字也按缩放后的尺寸重新栅格化，不会糊。

```js
zoom = Math.min(视口宽 / 1920, 1)   // 屏幕宽于 1920 时不再放大，避免糊
```

## 每页高度从哪来

按优先级自动判断，不需要手写：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | `<img class="shot">` 的宽高 | 优先用图片真实比例；图片没加载完时读 `width`/`height` 属性，所以配 `loading="lazy"` 也不会跳版 |
| 2 | `data-h="1440"` | 手动指定像素高，坐标要跟 Figma 严格对齐时用 |
| 3 | 内容自动量高 | 两者都没写时，浏览器量一遍内容撑开的高度 |

三种页面可以混在一套里：切图页、固定高度页、文案撑开页。

## 两种浏览方式

默认是**连续滚动**，页与页之间没有间隙，一路往下看。

HUD 上的按钮或按 `M` 可以切到**逐页预览**：一次一页、每页各自缩放保证整页完整可见，方便评审和投屏；再按一次回到连续滚动。

逐页预览下还有 `data-fit` 控制缩放策略：

- `data-fit="slide"`（默认）每页各自缩放，每页都尽量大。
- `data-fit="uniform"` 所有页统一按最高的一页缩放，翻页时字号不变，但矮页面会留白。

## 连续滚动自带的东西

- **顶部进度条**：跟着滚动位置走，长页面有位置感。
- **右侧章节点**：每一页一个点，滚动时自动高亮，点一下平滑滚到那一段。不需要就把 `index.html` 里的 `<div class="dots">` 删掉。
- **懒加载友好**：`.shot` 图片带上 `width`/`height` 属性后，即使加 `loading="lazy"` 也能在加载前算对高度，不会出现滚动条乱跳。

## 文件

```
outputs/
  index.html        ← 页面骨架 + HUD，切图内容由脚本写入
  styles.css        ← 舞台、缩放、进度条、章节点
  app.js            ← 量高 + 缩放 + 连续滚动/逐页预览/全屏/打印
  tools/build.py    ← 扫描 assets/，生成 <picture> + srcset，写入每一页
  tools/optimize.py ← PNG → 分级 AVIF/WebP，顺带生成模糊占位图
  assets/           ← 导出的切图，优化后是 NN@1280w.avif 这一套
  assets/lqip/      ← 20px 模糊占位图，构建时内联进 index.html
  hotspots.json     ← 可选，给切图加可点区域
```

直接双击 `index.html`，或起本地服务（推荐，避免个别浏览器对本地文件的安全限制）：

```bash
cd outputs
python3 -m http.server 8000
```

## 切图命名规则

文件名决定页面上从上到下的顺序，规则只有两条：

1. **以两位序号开头**，严格按从上到下的顺序：`01`、`02` …… `09`、`10`、`11`。补零是为了排序正确（不补零时 `10` 会排到 `02` 前面）。超过 99 页用三位。
2. **后面跟英文短名**，方便认：`01-hero`、`02-features`、`03-pricing`、`04-faq`。

配合 Figma 批量导出最省事：**先把 Figma 里的 Frame 按这个规则改名**，然后全选 → Export → `PNG` + `2x`，Figma 会自动产出 `01-hero@2x.png`、`02-features@2x.png`，命名直接就对了。

其他要求：

- 只用小写英文、数字、`-`，不要空格、中文和其他符号。
- 只导 2x。1920 导成 3840 宽，Retina 屏才清晰；浏览器会自动降采样，不用再单独导 1x。
- 导出用 **PNG**（或 Figma 的 WebP）都行，`tools/optimize.py` 会统一转成分级 AVIF，不用自己压。
- 只给纯色块的话 PNG 本来就小；照片、渐变、插画 PNG 会很大，那也没关系，转档时会被压下来。
- 每张图宽度必须是 1920 的整数倍，不要手动裁掉左右边。
- 页与页之间的留白留在图里，不要靠 `margin` 补，否则会和其他页对不齐。

## 清晰度和加载速度怎么平衡

这两件事不冲突，冲突的是「无脑导大图」。按下面的顺序做，可以既锐利又快。

**1. 密度只导 2x，不要 3x/4x**

设计稿 1920 宽 → 导出 3840 宽就够了。文件体积随倍率平方增长，3x 是 2x 的 2.25 倍大，但肉眼在正常屏幕上是看不出差别的。

**2. 格式用 AVIF，WebP 兜底**

| 格式 | 同画质相对 WebP | 适用 |
| --- | --- | --- |
| AVIF（q68） | 小 40–60%，边缘反而更锐 | 默认。浏览器支持率已 97%+ |
| WebP（q86） | 基准 | 老浏览器兜底，`<picture>` 自动降级 |
| PNG | 大 4–10 倍 | 只在需要无损时用 |

实测（同一张图、同一分辨率）：AVIF q68 是 59 KB，文字边缘 48.0 dB；WebP q90 是 144 KB，边缘 47.3 dB。
**体积只有 41%，字还更锐**。所以不用在「清晰」和「快」之间取舍。

`tools/optimize.py` 会把 PNG 一次性转好，默认 `--avif-q 68 --webp-q 86`。

**3. 页面必须切开，不要一张两万像素的长图**

这是速度上最要紧的一条，比格式选择影响大得多。一整张超长图浏览器会一次性解码，内存暴涨，手机上很可能直接白屏。按 Figma 的 Frame 切开之后，配合 `loading="lazy"` 只加载视口附近的，首屏快很多。

单张图高度建议不超过 6000px，`build.py` 超了会提醒你。

**4. 首屏预加载，其余懒加载**

`build.py` 已经做了：第一页 `fetchpriority="high"`，后面的 `loading="lazy"`。

**5. 一份源图出五档，浏览器自己挑**

只导 2x 时，手机（屏宽 390）会下载 3840 宽的图，属于过量；反过来笔记本盯 3840 也是浪费。
`optimize.py` 会把每张图导出 1280 / 1920 / 2560 / 3200 / 3840 五档 AVIF，页面用 `<picture>` 让浏览器按「窗口宽度 × 像素密度」选最省的那一档：

```html
<picture>
  <source type="image/avif" srcset="assets/01@1280w.avif 1280w, … assets/01@3840w.avif 3840w"
          sizes="(max-width: 1920px) 100vw, 1920px" />
  <source type="image/webp" srcset="assets/01@1920w.webp 1920w" sizes="…" />
  <img class="shot" src="assets/01@1920w.webp" width="1920" height="1080" … />
</picture>
```

`sizes` 是绝对宽度，所以不管页面怎么缩放，选档都是确定的：

| 设备 | 需要的宽 | 实际下载 | 首屏 | 整本 17 页 |
| --- | --- | --- | --- | --- |
| iPhone 15 | 1179 | 1280 | 23 KB | 1.1 MB |
| iPad Pro 11 | 1668 | 1920 | 34 KB | 1.9 MB |
| 1080p 外接屏 | 1920 | 1920 | 34 KB | 1.9 MB |
| MacBook 13/14" | 2880–3024 | 3200 | 59 KB | 3.5 MB |
| 4K / 5K 屏 | 3840 | 3840 | 76 KB | 4.1 MB |

**6. 加载位先用模糊占位图顶上**

`assets/lqip/*.webp` 是 20px 宽的缩略图，构建时以内联 base64 写进每一页的 `background-image`。
慢网下滑动时看到的是糊掉的本页预览，而不是一片白，等真图下载完再无缝盖上去。
17 页加起来只占 index.html 约 5 KB。

**7. 每次 build 会报体积**

```
01     高  1080  最高档  3840px    76 KB
02     高  1080  最高档  3840px    56 KB

共 17 页，最高档合计 4.1 MB，已写入 index.html
```

单张最高档超过 600 KB、或最高档合计超过 8 MB 会给出提醒。

## 一键生成页面

图按规则放进 `assets/` 后，一条命令跑完「转档 + 生成页面」：

```bash
cd outputs
python3 tools/optimize.py
```

`optimize.py` 做四件事：

1. 把每张 PNG 转成 1280/1920/2560/3200/3840 五档 AVIF，外加 1920 宽的 WebP 兜底；
2. 顺手生成 20px 的模糊占位图 `assets/lqip/`；
3. 原图移到 `../png-originals/<时间戳>/` 留档，仓库里只留压好的图；
4. 调 `build.py` 重写 `index.html`。

只改了 CSS/文案、图片没动时，可以只跑 `python3 tools/build.py`。它扫描 `assets/`，按文件名自然排序，读出每张图真实尺寸（不看文件名后缀，改名也不会算错高度）：

```
01     高  1080  最高档  3840px    76 KB
02     高  1080  最高档  3840px    56 KB

共 17 页，最高档合计 4.1 MB，已写入 index.html
```

加 `--eager` 可以关掉懒加载。

可调参数：`--avif-q 72`、`--webp-q 90`、`--keep`（转换后把原图留在 `assets/`）。

### 顺手埋热点

在 `outputs/` 下建 `hotspots.json`，坐标直接抄 Figma 的 X/Y/W/H，脚本会一起生成：

```json
{
  "01": [
    { "href": "/register", "x": 120, "y": 900, "w": 300, "h": 88 }
  ]
}
```

## 页面写法

### 整页切图

```html
<section class="slide">
  <img class="shot" src="assets/01-hero@2x.png" width="1920" height="2400" loading="lazy" alt="" />
</section>
```

`width`/`height` 填设计稿上的原始尺寸（1920 × 实际高度），不是 2x 的像素值。这两个属性给浏览器用来在图片加载前算好占位高度。

### 固定高度 + 热点

```html
<section class="slide" data-h="1080">
  <a class="hotspot" href="/register"
     style="left: 120px; top: 782px; width: 300px; height: 88px"></a>
</section>
```

### 纯文字排版

不写 `data-h`，内容撑多高就多高：

```html
<section class="slide">
  <div class="demo">…</div>
</section>
```

## 快捷键

`F` 全屏，`P` 导出 PDF，`M` 切换连续滚动 / 逐页预览，`?` 看提示。逐页预览下额外支持 `← →`、空格、`PageUp/PageDown` 翻页和数字键跳页。

## Figma 侧怎么导

1. 每个 Frame 宽度统一 1920，高度随意，一页一个 Frame，按从上到下顺序命名。
2. 隐藏参考线、网格、多余图层，避免被一起导出去。
3. 选中 Frame（或全选）→ Export → `PNG` + `2x`（1920 宽导出为 3840 宽）。网页里仍按 1920 的坐标排布。
4. 图标、插画单独导 `SVG`，矢量放大不虚。
5. 导图前确认字体已加载，否则会回退成默认字体导致排版变化；网页里用到商业字体需要另行授权。

## 导出 PDF / 分享

- 导出 PDF：点 HUD 的「导出 PDF」，目标位置选「另存为 PDF」，边距设无、勾选背景图形。每页会自动分页。
- 在线分享：整个 `outputs/` 目录拖到 Netlify Drop / Vercel / Cloudflare Pages，几十秒拿到公网地址。
- 只发文件：HTML + assets 打包发出去，对方双击就能看，不用装任何东西。

## 常见坑

- 图片发虚：导出用了 1x，改 2x。
- 页与页之间有缝：多半是切图本身带了白边，或给 `.slide` 加了 `margin`。检查切图边界。
- 排序乱了：文件名没补零，`10` 排到了 `02` 前面。
- 超宽屏（>1920）两侧留白：故意不放大。想强行铺满，把 `app.js` 里 `layout()` 的 `Math.min(size.w / STAGE_W, 1)` 去掉 `, 1`。
- 手机上字太小：等比缩放的必然结果。要在手机上可读，得单独写响应式断点，而不是靠缩放。
- 图片很多很卡：保持 `loading="lazy"` 和 `width`/`height` 属性，或改用 WebP。
